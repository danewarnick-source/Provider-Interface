# Provider Interface (HIVE) — read me first
Multi-tenant compliance platform for Utah DSPD (disability services) providers. AI engine "Nectar" (AWS Bedrock) advises and flags; it never fabricates documentation or acts unreviewed. First tenant: True North Supports (TNS), running HHS, SLN, SLH, SEI, DSI. State contract DHHS91172 has been in effect since 2026-07-01; build to it.

This file holds only what you can't learn from the code: what breaks the platform, facts about the live system, and domain truths that look like bugs. How we work together (plans, behavior tables, PR bodies, UI conventions, prompt writing, code style) is in `docs/agent-process.md`; read it for a **build** (a new screen or flow), skip it for a **fix**.

## Fix vs build
- Dane tests the UI on the PR's Vercel preview. Don't write e2e tests, take screenshots, or reproduce bugs in a browser unless the prompt asks. Reproduce the cheapest way (a unit test, a SQL query, the API logs) and only when the cause isn't clear from reading.
- **A fix** (bug, copy, one existing screen's behavior): read the code and, for any write, the live table and its RLS; ask only if a user-visible behavior is open; change it; unit-test the logic (pure functions in `lib/`, no regex-over-source "source lock" tests); run **Checks** once; PR body = what broke and why, what changed, a click-through list for Dane, what was deleted, any DB change.
- **A build**: plan and behavior table first, wait for approval (`docs/agent-process.md`).
- Replace means delete: when you replace a function, component, route, table or column, delete the old one in the same PR and grep for zero references. No `legacy`/`old`/`v2` copies, no feature flags keeping both paths alive.

- **Owner-only under RLS:** `organization_members`, `invitations`, `access_presets`, `access_assignments`. A server function that lets an Admin write them does its own checks (`requireCategory`, scope, "only an Owner acts on an Owner"), then writes with the service-role client. ## Domain truths (do not "simplify" these away)
- Atomic shift = client + service code + staff + time window. A client is scheduled or billed only for codes with an active row in `client_billing_codes` (the "1056"). No authorization → no shift, no billing.
- Quarter-hour codes round each ENTRY to the nearest quarter hour (`Math.round(duration / 15min)`); never alter raw timestamps; sum per-entry units, never round a summed total. `computeEntryUnits()` in `src/lib/billing-units.ts` is the only correct path. Known defects (ask before touching): some screens bill from `rounded_clock_in/out`; admin time edits overwrite `clock_in`/`clock_out`.
- EVV-mandated codes (geofence + UEVV): COM, HSQ, PAC, ACA, CHA, RP2, RP3, SLH, SLN, CMP, CMS (`src/lib/evv-codes.ts`). Everything else, incl. SEI, RHS, HHS, DSI, captures time for payroll/evidence only.
- Daily-rate codes: HHS, RHS, PPS, DSG, RL6, RP4, RP5, SED (`src/lib/service-billing.ts`). HHS/RHS/DSI/SEI rates are per-client from `client_billing_codes.rate_per_unit`; SLH/SLN are table rates.
- RHS = staffed homes: staff clock for payroll (not EVV) and may run nested 1:1 segments (DSI/SEI) via `parent_shift_id`; segments are NOT overlap conflicts and the staff doesn't count toward coverage during one. HHS = host homes: hosts NEVER clock or appear in scheduling; their artifact is the daily note + overnight confirmation (no overnight = unbillable day); agency staff visits into host homes ARE timed shifts.
- Billable HHS/residential day = attendance Present AND a daily note → `hhs_daily_records_v.billable`; otherwise `blocked_reason`. The view exists only live, counts notes in any status, has no authorization-date filter, omits PPS.
- Summary cadences (DHHS91172): quarterly (due 15 days after quarter end) for most codes incl. HHS/RHS/DSI/SLH/SLN; MONTHLY for SEI, SJD, CMP, CMS, PN1/PN2 (SEI summaries go into the state's UPI portal by the 15th); PBA = monthly financial statements. UPI is admin-only.
- Conflict engine: back-to-back shifts (end == next start) are NOT overlaps; segment-within-parent is NOT a conflict; 2:1 staffing needs a rights-modification warning; SLH/SLN overnight needs awake confirmation (asleep time unbillable); DSI max 6h/day; CMP/CMS max 8h/day, 40h/wk.
- Nectar: Gatekeeper (note coaching), Scrubber (pre-billing), Sentinel (deadlines), Auditor (packets). Always advisory: drafts marked, a human attests, never auto-publish, never invent content.

## Checks (once per PR, before the push; not per commit)
CI gates nothing yet; run these yourself on the finished branch:
1. `npm run build`. It regenerates `src/routeTree.gen.ts`; if that changed, commit it with the route change. Never commit a `src/routes/` change without it.
2. `npm run test:unit` (~20 s). It runs only the files listed in package.json: add every new `*.test.ts` there; on a merge conflict keep both lists. Node ≥ 22.6.
3. `npx eslint <changed files>`.
4. `NODE_OPTIONS=--max-old-space-size=8192 npx tsc --noEmit` only if you changed types, a server function's input/output, or `types.ts`. It takes minutes.
